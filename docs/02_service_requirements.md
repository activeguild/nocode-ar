> **「印刷物にかざすと動き出す」販促 AR を、担当者が自分で 30 分で作って、アプリなしで配れる。**

サービス仮名: （未定。開発者側で仮置き可）

## 2. 初期ターゲット（ビーチヘッド）

**展示会・イベントに出展する中小〜中堅企業のマーケティング／販促担当者**。
ユースケースの芯は「印刷した販促物（チラシ・パネル・名刺・ノベルティ・パッケージ）に QR を載せ、来場者がアプリなしでスマホをかざすと動画や 3D が現れ、その場で資料請求や LINE 友だち追加に誘導する」こと。

隣接ターゲット（MVP 後に横展開）: 中小印刷会社の提案メニュー、自治体・観光イベント、制作会社。

---

## 3. ペルソナ

### 3.1 作成者ペルソナ: 佐藤さん（35 歳、BtoB 製造業のマーケティング担当）

- 従業員 150 名の産業機器メーカー。マーケ部は 3 名。年 4 回の展示会出展と、年 2 回の製品カタログ改版を担当。
- デザインは Canva とパワポ、動画は制作会社に発注。コードは書けない。
- 困りごと:
  - ブースでは「声かけの数」を上司に求められるが、来場者が足を止めてくれない。
  - 製品の内部構造や動作を紙のパネルでは伝えきれない。動画はあるが、QR で YouTube に飛ばすだけでは印象に残らない。
  - 制作会社に AR を頼むと見積が数十万円・納期 1 か月以上で、出展のたびに頼めない。
  - 月 4 万円のツールは稟議が必要。月 1 万円台なら部の予算で決められる。
  - 2025〜2026 年に有名な AR ツールが次々終了したニュースを見て、「作っても消えるのでは」と不安。
- 成功の定義: 出展当日までに AR 付きチラシが間に合い、ブースで体験してもらい、名刺・資料請求・LINE 友だちが取れる。終了後に「何人が体験したか」を上司に報告できる。

### 3.2 体験者ペルソナ: 来場者（展示会に来た購買担当・技術者）

- 自分の iPhone または Android を持っている。アプリは入れたくない。通信は会場の混雑した回線。
- QR を読んで Web ページを開くことには慣れている（決済・広告で日常的に経験）。
- 期待: かざしたら数秒で何か起きる。面白ければ写真を撮って同僚に見せる。興味があれば資料を請求する。

## 4. ユーザーストーリー

優先度の定義: **Must** = MVP に必須（これがないと PMF 検証ができない）、**Should** = MVP 直後に欲しい、**Could** = 将来検討。

### 4.1 Must（MVP 必須: 7 件）

| ID | ストーリー | 受け入れの目安（マーケター視点） |
| --- | --- | --- |
| M1 | 作成者として、印刷物の画像（チラシやパネルのデザインデータ）をアップロードし、それを「かざす対象」として登録したい。来場者がその印刷物にスマホを向けると AR が起動してほしい。 | 一般的なチラシ・名刺・パネル画像で起動する。登録時に「この画像は認識しにくい」と分かる案内があるとなお良い。 |
| M2 | 作成者として、かざす対象の上に表示するコンテンツ（動画、画像、3D モデルのいずれか）をアップロードし、位置と大きさを画面上で直感的に調整したい。コードは書きたくない。 | ブラウザ上の操作だけで完結し、プレビューで配置結果が見える。対応フォーマットは一般的なもの（例: MP4、PNG/JPG、GLB）で、作成者が変換作業を求められない。 |
| M3 | 作成者として、AR 体験の中に「行動ボタン」（例: 資料請求フォームへ、LINE 友だち追加、Web サイトへ）を最低 1 つ置きたい。来場者がその場で次の行動に移れてほしい。 | ボタンのラベルとリンク先 URL を設定できる。タップで外部ページが開く。 |
| M4 | 作成者として、作った AR を「URL と QR コード」で公開したい。来場者は **アプリをインストールせず**、iPhone の Safari と Android の Chrome の標準ブラウザで体験できてほしい。 | QR 画像をダウンロードして印刷データに貼れる。iOS/Android の現行主要機種で動作する。カメラ許可以外の操作を来場者に求めない。 |
| M5 | 作成者として、公開前に自分のスマホで実機プレビューして、動作とコンテンツの見え方を確認したい。 | 編集画面からプレビュー用 QR/URL が出て、スマホで即確認できる。公開前に印刷物を刷り直すリスクを避けられる。 |
| M6 | 作成者として、公開後も同じ QR のまま内容（動画・ボタン・配置）を差し替えたい。印刷物は刷り直したくない。また、公開を停止・再開できてほしい。 | 差し替え後、再印刷なしで体験内容が更新される。停止中に QR を読むと「終了しました」等の案内が出る。 |
| M7 | 作成者として、AR ごとに「体験された回数」と「行動ボタンのタップ回数」を見たい。上司に成果を報告したい。 | ダッシュボードで AR 単位の数値を期間指定で確認できる。来場者の個人情報は取得しない。 |

補足: アカウント登録・ログインは M1〜M7 を成立させる前提として必要（作成者が自分の AR を管理できること）。ただし、登録手順は最小限（メールアドレス程度）にする。

### 4.2 Should（MVP 直後）

| ID | ストーリー |
| --- | --- |
| S1 | 作成者として、印刷物なしでも使える「床に 3D モデルを置く」AR（製品を実寸で机上に置いて見せる）を作りたい。 |
| S2 | 作成者として、「製品紹介動画 + 資料請求ボタン」「フォトフレーム + SNS シェア」のようなテンプレートから始めたい。 |
| S3 | 作成者として、有料プランに自分でアップグレードし、クレジットカードまたは請求書で支払いたい。無料プランの制限（公開 AR 数・体験回数・ロゴ表示）が明示されていてほしい。 |
| S4 | 作成者として、体験画面からサービスのロゴを消し、自社ロゴや自社ドメインで配信したい（有料）。 |
| S5 | 作成者として、作成した AR の素材（動画・画像・3D）と設定を手元にダウンロードしておきたい。サービス終了や乗り換えの不安を減らしたい。 |
| S6 | 作成者として、チームメンバーを招待して同じ AR を編集したい。 |
| S7 | 作成者として、体験画面の背景色・ボタン色など最低限のブランド調整をしたい。 |
| S8 | 作成者として、AR の公開期間（開始日・終了日）を設定したい。 |

### 4.3 Could（将来）

| ID | ストーリー |
| --- | --- |
| C1 | 複数地点を巡る AR スタンプラリー（観光・自治体向け）。 |
| C2 | 顔フィルタ／フォトフレーム型の AR。 |
| C3 | 多言語（英語・中国語）の体験画面。 |
| C4 | LINE 公式アカウント、HubSpot 等とのリード連携。 |
| C5 | 印刷会社向けの代理店（再販）プラン。 |
| C6 | 空間認識（SLAM/VPS）を使う位置固定 AR。 |
| C7 | Apple Vision Pro・スマートグラスでの閲覧。 |

## 5. MVP のスコープ

### 5.1 含める（Must のまとめ）

1. 印刷物画像をターゲットにした AR の作成（M1, M2）
2. 行動ボタン（M3）
3. URL + QR での公開、アプリ不要の体験（M4）
4. 実機プレビュー（M5）
5. 同一 QR での内容差し替え・公開停止（M6）
6. 体験回数・ボタンタップ回数の計測（M7）
7. 作成者アカウント（最小限）

### 5.2 あえて含めない（スコープ外）

| 項目 | 理由 |
| --- | --- |
| ネイティブアプリ（iOS/Android） | アプリ不要が中核価値。 |
| 空間認識・位置固定 AR（SLAM/VPS）、ロケーション AR | 8th Wall OSS 化でも非公開の高度機能で、MVP の価値検証に不要。 |
| 顔トラッキング・フィルタ | Snap/TikTok が無料で提供しており、ビーチヘッドの用途ではない。 |
| 3D モデルの制作・変換代行 | 3D 制作は別事業。MVP では「持っている動画・画像・3D を載せる」に限定。 |
| コード編集（カスタム JS） | ノーコードが中核価値。コードを求める代理店層は初期ターゲット外。 |
| 決済機能 | Should（S3）。MVP 期間は手動請求で代替可。 |
| チーム機能・権限管理 | Should（S6）。 |
| Vision Pro・スマートグラス対応 | 2026 年時点で配信先として時期尚早。 |
| 来場者の個人情報取得（フォーム内蔵） | 外部フォーム/LINE へのリンクで代替し、個人情報の保管責任を MVP では負わない。 |

## 6. 制約（守るべき前提）

| # | 制約 | 背景 |
| --- | --- | --- |
| K1 | **アプリインストール不要**。来場者は QR を読んで標準ブラウザ（iOS Safari / Android Chrome の現行版）だけで体験できる。 | 日本市場でのアプリ忌避、COCOAR 等アプリ型との差別化。iOS Safari は WebXR AR 非対応のため、iPhone でも動く方式が必要（方式は開発者判断）。 |
| K2 | **ノーコード**。作成者はコードを書かず、ブラウザ上の操作だけで作成・公開・更新できる。 | ターゲットがマーケ担当者。 |
| K3 | **スマホで動く**。体験は一般的なスマホ（目安として発売から 3〜4 年以内の機種）で、会場の混雑回線でも実用的に起動する。起動時間の具体目標は開発者と合意して決める（仮: QR 読み取りから数秒以内）。 | 展示会会場での利用が前提。 |
| K4 | **日本語 UI**。作成画面・体験画面・案内文はすべて日本語（将来の多言語化を妨げない）。 | 国内ビーチヘッド。 |
| K5 | **カメラ映像を保存・送信しない**。体験者のカメラ映像は端末内でのみ処理し、サーバーに送らない。計測は体験回数・タップ回数など個人を特定しない集計に限る。 | 来場者の安心感、個人情報保護。 |
| K6 | **作成者の資産を人質にしない**。作成者がアップロードした素材は作成者のもので、将来ダウンロードできる設計を妨げない（MVP では S5 として後続）。 | プラットフォーム終了ラッシュへの不安に応える。 |
| K7 | **作成から公開まで 30 分以内**を目指す（初回利用者が、手元の素材を使って）。 | コンセプトの中核。 |
| K8 | **汎用フォーマット**。入力は MP4 / PNG / JPG / GLB など一般的な形式に限り、独自形式への変換を作成者に求めない。 | 作成者の手間削減、乗り換え容易性。 |

## 7. 成功指標（PMF 判定）

数値目標は仮置きであり、初期ユーザー 10〜20 社の実績を見て見直す。

| 区分 | 指標 | 仮目標 | 測り方 |
| --- | --- | --- | --- |
| 活性化 | 登録者のうち **初回 AR を公開**した割合 | 40% 以上 | サービス内ログ |
| 活性化 | 登録から初回公開までの所要時間（中央値） | 30 分以内 | サービス内ログ |
| 価値実感 | 公開 AR あたりの **体験回数** | 1 イベントあたり 50 回以上（要検証） | M7 の計測 |
| 価値実感 | 体験から行動ボタンへの **タップ率** | 10% 以上（要検証） | M7 の計測 |
| 継続 | 初回公開から 90 日以内に **2 本目の AR を公開**した割合 | 30% 以上 | サービス内ログ（展示会の季節性を考慮し 90 日） |
| 継続 | 翌四半期の継続利用率（有料アカウント） | 60% 以上 | 契約データ |
| 収益 | 無料 → 有料転換率 | 5% 以上 | 契約データ |
| 推奨 | NPS | 30 以上 | 公開後アンケート |
| 定性 | Sean Ellis 型質問「このサービスが使えなくなったらどう感じるか」で「非常に困る」の割合 | 40% 以上 | アンケート |

PMF 判定の考え方: 「2 本目公開率」と「有料転換率」が目標を超え、かつ体験回数が実際に上司報告に使われている（インタビューで確認）状態を PMF の初期シグナルとする。

## 8. 価格仮説

| プラン | 価格（仮） | 内容（仮） | 根拠・狙い |
| --- | --- | --- | --- |
| フリー | 0 円 | 公開 AR 1 本、体験回数 月 100 回まで、サービスロゴ表示 | 「まず作ってみる」を促す。LESSAR / palanAR の無料枠と並ぶ入口。 |
| スタンダード | 月額 9,800 円（税別）または 1 プロジェクト 19,800 円の都度払い（要検証） | 公開 AR 10 本、体験回数 月 5,000 回、ロゴ非表示、計測 | palanAR（38,500 円）と無料枠の間の空白を狙う。担当者裁量で決裁できる価格帯。 |
| ビジネス | 月額 29,800 円（税別）（要検証） | 公開 AR 無制限、体験回数 月 50,000 回、独自ドメイン、チーム | 印刷会社・制作会社・複数ブランド運用向け。 |

- 価格はユーザーインタビューと「都度払い vs 月額」のテストで検証する。展示会は季節性があるため、都度払いの需要が月額より強い可能性がある。
- 請求書払いは国内の法人需要として Should（S3）で対応。

## 9. 開発者への引き継ぎ事項（要求の意図）

- 「印刷物にかざす」「アプリ不要」「30 分で公開」「数字で報告できる」の 4 点が要求の核。要件定義ではこの 4 点が落ちていないかを最初に確認する。
- iOS Safari での動作は必須条件。Android だけで成立する方式は不可。
- MVP は Must 7 件に絞る。Should 以降を先に作らない。
- 成功指標（M7 の計測）は後付けではなく、MVP の公開初日から取れること。
- 技術選定は開発者に委ねるが、K5（カメラ映像を送らない）と K6（資産をロックインしない）は設計で担保すること。
