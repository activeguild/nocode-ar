## 0. 要求の核 4 点の確認（第 9 節「要求の意図」に対する回答）

| 要求の核 | 本書での担保 |
| --- | --- |
| 印刷物にかざす | FR-3（ターゲット画像登録）、FR-7（閲覧ページの画像トラッキング）。iOS/Android 共通で動く **画像トラッキング方式（MindAR）** を採用（§3） |
| アプリ不要 | NFR-1（対応ブラウザ）、FR-7。WebXR / ARCore に依存しない方式のため、iPhone Safari と Android Chrome で同じ体験になる |
| 30 分で公開 | FR-2〜FR-6 の画面数を 4 画面（一覧・編集・公開・計測）に絞り、ターゲット画像の処理をブラウザ内で完結させる。受け入れ基準 AC-K7 で所要時間を測る |
| 数字で報告できる | FR-9（計測ダッシュボード）。公開初日から体験回数とボタンタップ回数を記録（FR-7-6）。個人を特定する情報は記録しない（NFR-6） |

iOS Safari 必須（第 9 節）: 画像トラッキング方式は iOS Safari のカメラ + WebGL で動作するため満たす。Android のみで成立する WebXR 方式は MVP では使わない。

## 1. 用語

| 用語 | 意味 |
| --- | --- |
| 作成者 | サービスにログインして AR を作る人（ペルソナ: 佐藤さん） |
| 体験者 | QR を読んでスマホで AR を見る人（ペルソナ: 来場者） |
| プロジェクト | 1 つの AR 体験の単位。1 つのターゲット画像 + 1 つのオーバーレイ + 行動ボタン + 公開状態 + 計測を持つ |
| ターゲット画像 | かざす対象となる印刷物の画像（チラシ等のデザインデータ） |
| ターゲットデータ | ターゲット画像から生成する認識用データ（MindAR の `.mind` ファイル）。作成者には見せない内部データ |
| オーバーレイ | ターゲット画像の上に表示するコンテンツ（動画 / 画像 / 3D モデルのいずれか 1 つ） |
| 行動ボタン | AR 体験中に画面に表示され、タップで外部 URL を開くボタン（CTA） |
| シーン定義 | ターゲット・オーバーレイ・ボタンの配置を記述した JSON。下書きと公開版の 2 つを持つ |
| 公開 URL / slug | 体験者がアクセスする固定 URL `https://<host>/v/<slug>`。slug はプロジェクト作成時に決まり、以後変わらない |
| プレビュー URL | 作成者が実機で下書きを確認するための URL `https://<host>/p/<token>` |

## 3. 技術方針（`04_architecture.md` §5 の採用と、要求への影響）

### 3.1 採用する構成

| 層 | 採用 |
| --- | --- |
| フロントエンド（作成画面・閲覧ページ） | React 19 + Vite + TypeScript。3D 処理は three.js（model-viewer と同じ 0.183 系） |
| 画像トラッキング | MindAR（`mind-ar` 1.2.5、MIT）。three.js ビルドを互換 shim 付きで使用。ターゲットデータ（`.mind`）の生成は **作成者のブラウザ内** で実行 |
| バックエンド | Node 22 + Express 5 + SQLite（`better-sqlite3`）+ ローカルファイル保存。単一プロセス・単一コンテナ |
| QR 生成 | `qrcode`（サーバ側で PNG / SVG を生成） |
| 認証 | メールアドレス + パスワードのセッション Cookie（§8.2 参照） |

### 3.2 iOS Safari の WebXR 非対応による判断と、要求への影響

| 判断 | 理由 | 影響する要求 | 影響の内容 |
| --- | --- | --- | --- |
| MVP の体験方式を **画像トラッキング（マーカー型）に一本化** する | iOS Safari には WebXR が無く、ブラウザ内で平面検出 AR を行う手段が無い。画像トラッキングはカメラ映像 + WebGL で動くため iOS/Android 両対応 | M1, M4, K1 | 要求どおり満たせる。ARCore / Google Play 開発者サービス（AR）も不要になるため、Android 側の対応端末が広がる |
| 「床に置く」AR（S1）は MVP に含めない | iOS では AR Quick Look に委ねる形になり、動画・ボタンを載せられない。要求上も Should | S1 | スコープ外のまま。実装する場合は model-viewer で 3D モデルのみ対応（`04_architecture.md` §2） |
| 動画は **音声ミュートで自動再生し、タップで音声 ON** | iOS Safari は音声付き動画の自動再生を禁止（ユーザー操作が必要）。`playsinline` + `muted` が必須 | M2, M4 | 体験者はカメラ許可以外の操作なしで映像を見られる。音声を聞くには 1 タップ要る（§8.2 に記載） |
| 閲覧ページは **Safari / Chrome 本体で開く** ことを推奨し、アプリ内ブラウザでは案内を出す | LINE 等のアプリ内ブラウザはカメラ利用が不安定 | M4 | QR は標準カメラアプリで読む前提。アプリ内ブラウザ検出時は「Safari（Chrome）で開く」案内を表示（FR-7-2） |
| MindAR は保守停止リスクがあるため **フォーク前提** で組み込む | 2024-01 以降更新なし。three.js 互換 shim で動作確認済み | — | 要求への影響なし。保守コストとして見込む |

### 3.3 技術検証で確認済みの事項

`04_architecture.md` §3 のとおり、本環境で install / build / ヘッドレス Chromium 実行まで確認済み。未確認は実機（iOS Safari、Android Chrome）でのカメラ・トラッキング品質であり、QA フェーズの実機検証に依存する（§9.3）。

## 4. 機能要件

記法: **FR-<画面>-<番号>**。各要件に 入力 / 処理 / 出力 / 異常系 を記す。異常系のメッセージ文言は日本語で実装時に確定する。

### FR-1 アカウント（登録・ログイン）

| ID | 要件 |
| --- | --- |
| FR-1-1 | **登録**。入力: メールアドレス、パスワード（8 文字以上）。処理: 重複チェック、パスワードはハッシュ化（argon2 または bcrypt）して保存。出力: ログイン状態でプロジェクト一覧へ遷移。異常系: 既登録メール → 「このメールアドレスは登録済みです」、形式不正 → 項目ごとのエラー表示 |
| FR-1-2 | **ログイン / ログアウト**。入力: メール、パスワード。処理: 照合しセッション Cookie（HttpOnly, Secure, SameSite=Lax）を発行。異常系: 不一致 → 「メールアドレスまたはパスワードが違います」（どちらが違うかは明かさない）。連続失敗 10 回で 15 分ロック |
| FR-1-3 | 作成者は自分のプロジェクトのみ閲覧・編集できる。他人のプロジェクト ID を指定した API 呼び出しは 404 を返す |
| FR-1-4 | 公開 URL / プレビュー URL / 計測イベント送信は認証不要 |
| FR-1-5 | MVP では確認メール送信・パスワード再設定メールを **実装しない**（§8.2 差分 D1）。再設定はオーナーが管理コマンドで行う |

### FR-2 プロジェクト一覧・作成

| ID | 要件 |
| --- | --- |
| FR-2-1 | **一覧**。出力: 自分のプロジェクトを更新日降順で表示。各行にプロジェクト名、状態（下書き / 公開中 / 停止中）、公開 URL、累計体験回数、累計タップ回数、「編集」「計測」ボタン |
| FR-2-2 | **作成**。入力: プロジェクト名（1〜60 文字）。処理: slug（英小文字・数字 8 文字、推測困難な乱数）を生成し、状態 = 下書きで保存。出力: 編集画面へ遷移。異常系: 名称空 → エラー |
| FR-2-3 | **削除**。確認ダイアログ後に削除。公開中の場合は「公開中です。削除すると QR からアクセスできなくなります」と警告。削除後に公開 URL を開くと「終了しました」画面（FR-7-8） |
| FR-2-4 | **名前変更**。編集画面の見出しからインライン編集 |

### FR-3 ターゲット画像の登録（M1）

| ID | 要件 |
| --- | --- |
| FR-3-1 | 編集画面の「1. かざす対象」セクションで、ターゲット画像を 1 枚アップロードする（ドラッグ&ドロップ / ファイル選択） |
| FR-3-2 | 入力形式: PNG / JPEG。上限 10 MB、長辺 8,000 px 以下。処理: ブラウザ内で長辺 1,024 px に縮小したコピーを認識用に使う（元画像はそのまま保存）。異常系: 形式外 → 「PNG または JPG を選択してください」、上限超過 → 「10 MB 以下の画像にしてください」 |
| FR-3-3 | **ターゲットデータ生成**。処理: アップロード直後に作成者のブラウザ内で MindAR Compiler を実行し `.mind` を生成、サーバに保存。進捗バーと「通常 10〜60 秒かかります」の案内を表示。生成中も他の入力（オーバーレイ・ボタン）は操作可能。異常系: 生成失敗 → 「画像の解析に失敗しました。別の画像をお試しください」（再試行ボタン） |
| FR-3-4 | **認識しやすさの判定**。処理: 生成時の特徴点数から 3 段階（良い / 普通 / 認識しにくい）を判定し、サムネイル横に表示。「認識しにくい」の場合は理由の候補（単色・グラデーションが多い、文字が少ない、繰り返し模様）と改善案（写真やロゴを含む面を使う、余白を減らす）を表示。判定は目安であり、登録はブロックしない |
| FR-3-5 | **印刷サイズ**。入力: ターゲット画像の実際の印刷幅（mm、任意、既定 210 = A4 横幅）。処理: 3D モデルの実寸表示とプレビューの見え方に使用。異常系: 10〜3,000 mm 以外は拒否 |
| FR-3-6 | 画像を差し替えると `.mind` を再生成し、オーバーレイの配置（相対座標）は維持する |

### FR-4 オーバーレイの編集（M2）

| ID | 要件 |
| --- | --- |
| FR-4-1 | 「2. 表示するコンテンツ」セクションで、オーバーレイを **1 つ** 登録する（動画 / 画像 / 3D モデルのいずれか。§8.2 差分 D3） |
| FR-4-2 | 入力形式と上限: 動画 MP4（H.264 + AAC）50 MB・推奨 1080p 以下 60 秒以内 / 画像 PNG・JPEG・WebP 10 MB / 3D モデル GLB（glTF 2.0 バイナリ）20 MB。異常系: 形式外・上限超過は FR-3-2 と同様のメッセージ。GLB は読み込み検証（three.js GLTFLoader）に失敗したら「この 3D ファイルは読み込めません」 |
| FR-4-3 | **配置編集（2D）**。出力: ターゲット画像を背景にしたキャンバス上にオーバーレイを重ねて表示。操作: ドラッグで移動、四隅ハンドルで拡大縮小（縦横比固定）、回転ハンドルで Z 軸回転、数値入力（X, Y, 幅 %, 回転°）。座標はターゲット画像の幅を 1.0 とする相対値で保存。既定値: ターゲット中央、幅 80% |
| FR-4-4 | **3D モデルの追加設定**。入力: ターゲット面からの浮き（0〜2.0、ターゲット幅比）、Y 軸回転、「自動で回転させる」トグル。出力: three.js プレビューでターゲット画像の上に実際の見え方（斜めからの視点）を表示 |
| FR-4-5 | **動画の追加設定**。入力: ループ再生（既定 ON）、「音声あり」トグル（ON の場合、体験画面にタップで音声 ON の案内を出す）。処理: ブラウザ内で 1 フレーム目のサムネイルを生成して配置編集に使う |
| FR-4-6 | **プレビュー（PC）**。ボタン「プレビュー」で、編集中のシーン定義を閲覧ページと同じ描画コードで表示する（カメラは使わず、ターゲット画像を背景に合成）。PC のカメラがある場合は「カメラでプレビュー」も可能（画面に映したターゲット画像を認識） |
| FR-4-7 | **保存**。処理: 変更は 2 秒のデバウンスで自動保存（下書き）。保存状態（保存済み / 保存中 / 保存失敗）を常時表示。異常系: 通信失敗 → 再試行、失敗が続く場合は「保存できませんでした。ページを再読み込みしてください」 |

### FR-5 行動ボタン（M3）

| ID | 要件 |
| --- | --- |
| FR-5-1 | 「3. 行動ボタン」セクションで、ボタンを 1〜3 個登録する。公開には **最低 1 個** が必要（FR-6-2） |
| FR-5-2 | 入力: ラベル（1〜20 文字、既定「資料を請求する」）、リンク先 URL（https:// または `line://` / `https://lin.ee/` 等の LINE 公式リンク）。異常系: URL 形式不正 → 「https:// から始まる URL を入力してください」 |
| FR-5-3 | 表示位置: 体験画面の下部に固定（画面内 2D。ターゲット追従はしない）。順序はドラッグで並べ替え |
| FR-5-4 | プリセット: 「資料請求」「LINE 友だち追加」「Web サイトへ」の 3 つから選ぶとラベルが入る（URL は作成者入力） |

### FR-6 公開・QR・プレビュー・差し替え・停止（M4, M5, M6）

| ID | 要件 |
| --- | --- |
| FR-6-1 | 「4. 公開」セクションに、公開 URL（固定）と状態、公開ボタン / 停止ボタン、QR ダウンロードを表示 |
| FR-6-2 | **公開前チェック**。処理: ターゲットデータ生成済み、オーバーレイ 1 つ、ボタン 1 つ以上、を満たさなければ公開ボタンを無効化し、不足項目を列挙 |
| FR-6-3 | **公開**。処理: 下書きシーン定義のスナップショットを「公開版」としてコピーし、状態 = 公開中、公開日時を記録。出力: 「公開しました」と QR。公開版はアセットを含めて不変（以後の下書き編集は反映されない） |
| FR-6-4 | **QR ダウンロード**。出力: PNG（1,024 px、誤り訂正レベル M、余白 4 モジュール）と SVG。QR の内容は公開 URL そのもの（短縮サービス等を介さない）。公開前でもダウンロード可能（印刷データの先行入稿のため。公開前に読むと FR-7-8 の「準備中」画面） |
| FR-6-5 | **実機プレビュー**。出力: 編集画面に常時「スマホで確認」ボタンがあり、押すとプレビュー URL `https://<host>/p/<token>` の QR を画面に表示。token はプロジェクトごとに固定（再発行ボタンあり）、推測困難な 32 文字 |
| FR-6-6 | プレビュー URL は **下書き** を表示し、閲覧ページと同じコードで動作する。画面上部に「プレビュー（未公開）」バッジを表示。計測イベントは記録しない |
| FR-6-7 | **差し替え（再公開）**。処理: 下書きを編集後「更新を公開」で公開版を差し替える。URL・slug・QR は不変。体験者側は次回アクセス時から新内容（キャッシュ制御: シーン JSON は `Cache-Control: no-cache`、アセットはハッシュ付き URL で長期キャッシュ） |
| FR-6-8 | 公開中に下書きが公開版と異なる場合、「未公開の変更があります」を表示 |
| FR-6-9 | **停止 / 再開**。処理: 停止で状態 = 停止中。公開版は保持し、再開で即時復帰。停止中に公開 URL を開くと FR-7-8 の「終了しました」画面 |
| FR-6-10 | 公開・停止・再公開の履歴（日時、操作）を保持し、計測画面に表示（FR-9-4） |

### FR-7 閲覧ページ（体験者向け、M4）

| ID | 要件 |
| --- | --- |
| FR-7-1 | **導入画面**。URL `/v/<slug>` を開くと、カメラ起動前に 1 画面: プロジェクト名、「カメラを起動してチラシにかざしてください」、「カメラを起動」ボタン。カメラ許可はこのボタン押下で要求する（iOS でユーザー操作起点が必要なため）。体験者に求める操作はこの 1 タップとカメラ許可のみ |
| FR-7-2 | **非対応・アプリ内ブラウザ検出**。処理: `getUserMedia` / WebGL 不可、またはアプリ内ブラウザ（LINE, Instagram, Facebook, X 等の UA）を検出したら、「Safari で開く」「Chrome で開く」の案内と URL コピー（iOS: 共有シート経由）を表示。異常系: カメラ許可拒否 → 「カメラの許可が必要です」と設定手順リンク |
| FR-7-3 | **トラッキング**。処理: カメラ映像を端末内で MindAR により解析し、ターゲット認識中はオーバーレイをターゲットに追従表示。カメラ映像はネットワークに送信しない（NFR-6）。認識待ちの間は画面に「チラシ全体が映るようにかざしてください」のガイド枠を表示。ターゲットを見失って 1 秒経過でガイドに戻る |
| FR-7-4 | **オーバーレイ描画**。動画: 認識開始で再生（ミュート・`playsinline`・ループ設定どおり）、見失いで一時停止、再認識で再開。「音声あり」設定時はスピーカーアイコンを表示し、タップで音声 ON。画像: 平面に表示。3D: GLB を読み込み、FR-4-4 の設定で表示。アセットは導入画面表示中に先読みする |
| FR-7-5 | **行動ボタン**。画面下部に FR-5 のボタンを表示（認識有無にかかわらず常時表示。認識前に押せないと離脱要因になるため）。タップで `window.open`（新規タブ）または LINE スキームへ遷移。タップを計測イベント `cta_tap` として送信してから遷移（`navigator.sendBeacon`） |
| FR-7-6 | **計測イベント送信**。`view_start`: カメラ起動成功時に 1 回。`recognized`: 初回のターゲット認識時に 1 回。`cta_tap`: ボタンごと。送信内容は slug、イベント種別、ボタン ID、OS 種別（iOS / Android / その他）のみ（NFR-6）。送信失敗時はリトライ 1 回、以後破棄（体験を妨げない） |
| FR-7-7 | **サービス表示**。画面上部に小さくサービスロゴ（将来の有料プランで非表示にできる設計。S4）。写真撮影を妨げないよう、UI は最小限 |
| FR-7-8 | **公開されていない場合**。停止中: 「この AR は終了しました」、公開前: 「準備中です」、存在しない slug: 「ページが見つかりません」。いずれもカメラは起動しない |
| FR-7-9 | **ローディング**。導入画面からカメラ起動までの進捗（ライブラリ読み込み・ターゲットデータ・コンテンツ）を 1 本のバーで表示。動画はストリーミング再生（全量ダウンロード待ちしない） |

| NFR-12 | **ブラウザ（作成者）**: PC の Chrome / Edge / Safari 最新 2 版。ターゲットデータ生成に WebGL 2 と 2 GB 以上の空きメモリ | |

## 6. データモデルと API

### 6.1 データモデル

```
User            id, email(unique), passwordHash, createdAt
Project         id, userId, name, slug(unique, 8字), status('draft'|'published'|'unpublished'),
                previewToken(unique), draftScene(JSON), publishedSceneId(nullable),
                targetPrintWidthMm, createdAt, updatedAt
Asset           id(ランダム 22 字), projectId, kind('target_image'|'target_mind'|'overlay'|'thumbnail'),
                mime, sizeBytes, storagePath, width, height, durationSec(nullable), sha256, createdAt
SceneVersion    id, projectId, scene(JSON, イミュータブル), publishedAt, publishedByUserId
PublishEvent    id, projectId, type('publish'|'unpublish'|'republish'), sceneVersionId, at
AnalyticsEvent  id, projectId, sceneVersionId, type('view_start'|'recognized'|'cta_tap'),
                buttonId(nullable), os('ios'|'android'|'other'), occurredAt(UTC), dayJst(YYYY-MM-DD)
```

シーン定義（`draftScene` / `SceneVersion.scene`）:

```jsonc
{
  "version": 1,
  "target": {
    "imageAssetId": "…",        // 元画像（PNG/JPEG）
    "mindAssetId": "…",         // ブラウザで生成した .mind
    "printWidthMm": 210,
    "quality": "good"           // "good" | "fair" | "poor"（FR-3-4）
  },
  "overlay": {
    "type": "video",            // "video" | "image" | "model"
    "assetId": "…",
    "thumbnailAssetId": "…",    // video のみ
    "transform": { "x": 0.5, "y": 0.5, "width": 0.8, "rotationDeg": 0 },   // ターゲット幅 = 1.0 の相対座標
    "video":  { "loop": true, "withAudio": false },                        // type=video
    "model":  { "lift": 0.1, "yawDeg": 0, "autoRotate": true }             // type=model
  },
  "buttons": [
    { "id": "b1", "label": "資料を請求する", "url": "https://…", "preset": "docs" }
  ]
}
```

- 個人を特定する項目は `AnalyticsEvent` に存在しない（NFR-6）。
- 素材は元形式のまま `data/assets/<projectId>/<assetId>.<ext>` に保存（NFR-8）。

## 7. MVP の受け入れ基準（QA 検証用）

各基準は「手順 → 期待結果」で検証できる形にする。実機は iPhone（iOS 16 以上、Safari）と Android（Android 10 以上、Chrome）を各 1 台以上。

| ID | 要求 | 受け入れ基準 |
| --- | --- | --- |

| AC-M1 | ターゲット登録 | (1) A4 チラシ相当の PNG（写真と文字を含む）をアップロードすると 60 秒以内に「良い」または「普通」の判定が表示される。(2) 単色に小さな文字だけの画像では「認識しにくい」と改善案が表示され、それでも登録はできる。(3) 登録した画像を印刷（またはディスプレイ表示）し、閲覧ページで 2 秒以内に認識される（NFR-2(c)） |

## 8. スコープ外と、要求との差分

### 8.1 スコープ外（要求 §5.2 をそのまま反映）

ネイティブアプリ、SLAM / VPS / ロケーション AR、顔トラッキング、3D 制作・変換代行、コード編集、決済、チーム・権限、Vision Pro / スマートグラス、来場者の個人情報取得（内蔵フォーム）。加えて Should（S1〜S8）、Could（C1〜C7）は MVP に含めない。

### 8.2 要求との差分（マーケター判断が必要な点）

| ID | 項目 | MVP での扱い | 理由 | 代替案 |
| --- | --- | --- | --- | --- |
| D1 | アカウント登録の方式 | メールアドレス + パスワード。**確認メール・パスワード再設定メールは送らない**（再設定はオーナーが手動） | MVP は外部サービス（メール配信）無しで動く構成。メール送信を入れると配信事業者の契約・ドメイン認証（SPF/DKIM）が必要で初期の立ち上げを遅らせる | (a) 初期 10〜20 社は手動対応で割り切る（推奨）。(b) マジックリンク方式にし、メール配信サービスを MVP に含める（+0.5 相対工数、外部契約） |
| D2 | 計測の粒度 | 「体験回数 = カメラ起動回数」「認識回数」「ボタンタップ回数」を **日別・OS 別** で集計。**ユニーク人数は数えない**。時間帯別は MVP 外 | K5（個人を特定しない）を厳格に守るため Cookie / 端末 ID を使わない。同一人物が 2 回体験すると 2 回と数える | (a) そのまま（推奨。上司報告には「体験回数」で十分と判断）。(b) 24 時間で消える匿名トークンでユニーク数を概算する（プライバシーポリシーへの記載が必要） |
| D3 | オーバーレイの個数 | 1 プロジェクトにつき **オーバーレイ 1 つ**（動画 / 画像 / 3D のいずれか）+ ボタン最大 3 つ | 要求 M2 の「いずれか」をそのまま採用。複数オーバーレイは配置 UI・重なり順・パフォーマンス（動画 2 本同時再生等）の複雑さが増し 30 分公開を阻害する | 複数が必要なら Should として次スプリントで対応（配置 UI は共通化しておく） |
| D4 | 動画の音声 | 自動再生は **ミュート**。音声ありはタップで ON | iOS Safari の仕様。回避不可 | 体験画面に「タップで音声 ON」の明示。音声が重要なら字幕入り動画を推奨する案内を作成画面に出す |
| D5 | 1 プロジェクト = 1 ターゲット画像 | 複数の印刷面（表裏、複数チラシ）を 1 つの AR にまとめる機能は MVP 外。別プロジェクト（別 QR）で対応 | MindAR は複数ターゲットに対応しているが、編集 UI が複雑になる | 次スプリント候補（S 相当）として明記 |
| D6 | QR からアプリ内ブラウザで開かれた場合 | 自動的に Safari / Chrome へ切り替える手段は無いため、**案内画面**で対応 | OS の制約（LINE 等のアプリ内ブラウザからの強制遷移は不可） | 印刷物に「標準カメラで読み取ってください」の一文を添える運用ガイドを提供 |
| D7 | 「認識しにくい」判定 | 特徴点数ベースの **3 段階の目安**。認識保証ではない | 実際の認識率は照明・印刷品質・端末に依存し、事前に確定できない | 実機プレビュー（M5）で確認する運用を案内文で推奨 |
| D8 | 無料プランの上限（公開 AR 数・体験回数）の **制御** | MVP では **制御しない**（計測のみ）。ロゴは常時表示 | 価格・上限が未決（要求 §10）。計測は取れるので後から制御を足せる | 上限値が決まり次第、制御を追加（+0.5 相対工数） |
| D9 | 行動ボタンの表示 | 画面下部固定（ターゲットに追従しない） | 追従ボタンは認識が途切れると押せず離脱要因。常時表示の方がタップ率に有利と判断 | 要求があればターゲット追従型をオプションとして追加 |
| D10 | 作成画面の対応ブラウザ | PC ブラウザが主対象。スマホでの作成は閲覧・軽微な編集まで | ターゲットデータ生成がスマホでは遅い（メモリ・CPU） | スマホ作成が要求なら、生成をサーバ側に移す（`canvas` 依存のビルド対応が必要） |

### 8.3 Should に対する設計上の配慮（実装はしない）

- S1（床置き）: `04_architecture.md` の model-viewer 経路を閲覧ページに追加できるよう、シーン定義に `mode` を将来追加できる構造にする。

- S8（公開期間）: `Project` に `publishFrom` / `publishUntil` を後から追加できる（FR-7-8 の分岐に乗る）。

### 9.2 テスト方針

| 種別 | 対象 | 手段 |
| --- | --- | --- |
| 単体 | シーン定義の検証、アセット検証（MIME・マジックバイト・上限）、slug / token 生成、集計 SQL、認可（他人のプロジェクトは 404） | Vitest |
| API | 認証、CRUD、公開 / 停止の状態遷移、イベント受付とレート制限 | Vitest + supertest（SQLite をテストごとに作成） |
| E2E（作成画面） | 登録 → プロジェクト作成 → ターゲット登録（`.mind` 生成）→ オーバーレイ配置 → ボタン → 公開 → QR ダウンロード → 停止 | Playwright（ヘッドレス Chromium、SwiftShader で WebGL） |
| E2E（閲覧ページ） | 導入画面 → カメラ起動 → 認識 → オーバーレイ表示 → ボタンタップ → 計測イベント | Playwright + Chromium のフェイクカメラ（`--use-fake-device-for-media-stream` と、ターゲット画像を動画化した `.y4m` を `--use-file-for-fake-video-capture` で投入）。認識成功までを自動検証 |
| 実機 | NFR-1 の端末での AC-M1(3)、AC-M4、AC-M5、AC-K3、AC-K5 | QA の手動チェックリスト（§9.3）。開発者はローカル HTTPS + 同一 Wi-Fi で随時確認 |
| 性能 | NFR-2 の転送量・時間 | Lighthouse（モバイル・4G スロットリング）と実機ストップウォッチ |
| 受け入れ | §7 全件 | QA が `docs/05_qa_report.md` に記録 |
